# 战斗、技能与飞行物链路

## 角色和资源 ID

`Heros` 表 ID 与运行时角色 ID 不相同。`ResManager` 通过 `eciHerosStart`（1000）区分英雄和魔物，hero 2 对应 `eciMageHF`（1002）。

当前战斗技能仍由 `CBattleRole.loadData()` 初始化，尚未完全接入英雄表的技能及伤害属性。各角色的技能对象独立创建。

## 调用过程

`CBattleFormation` 按房间和阵营维护编制，同角色 ID 的人数包含一名在场角色和后备人数；后备不创建实体。在场角色死亡时同步扣除一人并加载下一名，我方从右边界外、敌方从左边界外入场。补位角色先到指定站位再施法；加载期间仍计入剩余战力，防止提前离场或胜利结算。房间守军损失同步回房间数据，调整后备人数保留当前存活角色的血量。

1. `CCharactersManager` 创建角色并设置运行时 ID，再调用 `init()` 和 `loadData()`。
2. `CBattleRole` 负责入场、选技能、寻敌和施法调度。角色身体完整进入房间横向边界后才能开始施法；施法期间锁定技能和目标。

   技能选择优先采用最远射程，射程用于决定站位，冷却只决定何时施法。目标在射程内时原地等待冷却，避免法师因火球冷却而切换近战并持续前进。
3. `CSkillLanche` 保存本次施法目标及飞行物 ID。动画关键帧和动画结束回调共用一次发射标记，避免重复生成飞行物。
4. `CBattleRole.LauncheMissile()` 使用 `CResManager.getMissilePrefab()` 查找预制体，在房间表现层创建飞行物，向保存的施法目标位置发射。
5. `CMissile` 负责飞行、命中、爆炸和清理。每帧将整段飞行路径投影到房间横轴，命中路径上的第一个存活敌人；视觉高度和物理碰撞回调不决定伤害，避免高速穿透或越过前排。命中后立即停止继续判定伤害，完成通知只发送一次，表现结束后销毁节点。

寻敌按角色中心在战线上的距离排序，体型不改变前后顺序。入场、追击和补位移动都受敌方身体边界阻挡。补位途中接敌时立即结束强制跑位并开始正常交战，不能为了到达预设站位穿过敌人；前排死亡后才继续攻击后方。

`ResManager.missilePfb` 在 `Main.scene` 中配置。技能确定飞行物 ID，预制体确定表现；两层都需要检查。

## 火球变成黑魔法的原因

两个预制体曾同时引用 `animation/effect/fireball` 下的动画，而这些动画的帧图片已被改为 darkmagic 图片。火球预制体的初始图片虽然正确，动画播放时仍会被替换为黑魔法图片。

现将 darkmagic 动画独立放在 `animation/effect/darkmagic`，火球动画恢复使用 fireball 图片。修改某种飞行物时，应检查预制体和动画引用，避免修改共用动画连带改变其它飞行物。

## 验证

运行 `node tests/minor-invasion.cjs <typescript/lib/typescript.js 路径>`，检查角色技能、技能切换与锁定、入场限制、弹道目标、动画帧归属及飞行物生命周期。测试使用引擎替身，实际动画表现需在 Cocos 预览中确认。
